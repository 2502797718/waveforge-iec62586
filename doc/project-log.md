## 2. 架构演进

### 2.1 从“场景驱动”到“两层架构”

最初每个场景直接拼装旧 `wg_signal_t`，导致：

- 标准缺值被误读为“发生器不能生成”；
- 复杂调制只能通过新增场景实现；
- 场景与信号能力耦合，难以扩展。

分层后：

- **Signal Core** 定义分量、调制链、事件；
- **Preset Layer** 只填默认值，调用 `wg_program_add_*`；
- 两者产出同一个 `wg_program_t`，采样器只认 program。

### 2.2 旧字段兼容

旧 `signal.freq_hz/amp_pct/phase_deg/harmonics/interharmonics/tones/modulation` 继续接受：

- program 为空时走旧求值路径；
- program 非空时旧四类分量被忽略；
- 基波分量的幅值/相位可继承旧 `signal`；
- 旧 JSON 与等价 program 的输出差异为 0（逐点 `maxabs = 0`）。

## 4. 已知问题

### ISS-020（语义）全局相位跳变对谐波按 order 缩放

- **现象**：`phase_step +30°` 时，H3 实测 +90°，1.5 次间谐波 +45°，`tone` 不变。
- **原因**：偏移加在积分相位 φ 上，各分量使用 `order × φ`。
- **影响**：若用户期望“每条谱线绝对 +30°”，当前实现不满足。
- **状态**：待确认。可选方案：
  1. 保持现状（物理上等价于基波相位跳变，谐波自然跟随）；
  2. 增加逐分量绝对偏移事件（需要扩展事件类型）。

### ISS-019（资源）`wg_config_t` 约 121 KB

- **现象**：program 以值内嵌，`sizeof(wg_config_t)` ≈ 121 648 B；栈上两份约 242 KB。
- **影响**：默认线程栈裕量变小；主机测试未出问题。
- **状态**：已记录，暂不影响功能。
- **方向**：把 `program` 改为指针 + 堆分配，或提供 `wg_config_alloc()`。

### ISS-016（标准解释）A4.2.1 相间时序

- **现象**：条款文本要求各相在自身上升过零切换，图示以半周窗口表示位移，两者不能同时推出“相邻相严格 20 ms”。
- **实现选择**：段起点延时 + 本相过零吸附。
- **验收**：顺序、0 V 区间、过零残差；相间间隔仅记录。
- **状态**：待标准原图或实验室确认。

### 过期 exe（历史）

- 早期版本曾在仓库根放置 `wg.exe` / `selftest.exe` 预编译产物，行为可能与当前源码不一致。
- 开源化整理时已移除；现在所有构建产物都在 `build/`，并由 `.gitignore` 排除。
- 不要提交二进制，也不要用历史 exe 判断能力。

### 构建与仓库布局

- 公开仓库采用标准开源布局：`include/`、`src/`、`apps/`、`tests/`、`examples/`、`doc/`、`tools/`。
- 同时提供 `Makefile`（产物在 `build/`）与 `CMakeLists.txt`（目标 `waveforge`、`wg`、`selftest`）。
- `.gitignore` 已排除 `_private/`、`build/`、`runs/`、`standard-scan/`、`*.exe`、`*.bin` 等。
- CMake 使用方式见 [使用手册](user-manual.md) §2.3。

### 段时长约束

- 当前实现要求各段时长之和**等于**总时长（浮点余量 1e-9）。
- 早期文档曾写“不足按末段延续”，与实现不符；以本文与 [输入格式](input-format.md) 为准。

## 7. 维护约定

1. 修改信号模型、帧格式、配置解析或预设层后，按 [校验](verification.md) §7 重跑回归。
2. 不删除失败证据；修复后新增 run，并列记录。
3. 不把软件 PASS 写成硬件或 IEC 合格。
4. 标准数值变更必须注明来源；缺值继续用 `NO_DEFAULT`，不得外推。
5. 文档与代码不一致时，以代码与本文档的“当前实现”描述为准，并记录差异。
